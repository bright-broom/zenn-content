NextChat 2.15.8～2.16.1、または browser-use web-ui 2.0.0～3.0.0 を使っている場合は、API キーの扱いを確認してください。調査時点で実悪用や実際のキー漏えいは確認されていないため、まず対象バージョンと公開範囲を確かめ、必要な場合にキーのローテーションへ進むのが現実的です。

自分で AI チャットを立てたり、チームでブラウザー操作エージェントを共有したりすると、API キーは一度設定した後、普段は意識しにくい存在になります。しかし、そのキーが「どの通信を通るのか」「どこに保存されるのか」は、利用者自身の費用や情報を守るうえで見落とせません。

## 要点

NVD は対象期間内に、AI ツールの API キーに関する Security 脆弱性 2 件を新規登録しました。NextChat では、認証なしの攻撃者がサーバー設定の OpenAI API キーを外部ホストへ送信させ得ます。browser-use web-ui では、LLM API キーが平文の JSON ファイルとして保存されますが、取得には一時設定ディレクトリへの読み取りアクセスが必要です。

2 件の違いは、攻撃者がどこまで環境へ近づく必要があるかです。NextChat はネットワーク経由かつ認証なしで悪用できるため High、browser-use web-ui はローカルまたは共有ストレージへの読み取り権限が前提となるため Medium と評価しました。

## 自分の環境は対象か

| 対象バージョン | 2.15.8～2.16.1 | 2.0.0～3.0.0 |
| 確認済みの攻撃条件 | ネットワーク経由、認証不要、利用者操作不要 | 一時設定ディレクトリへのローカル読み取り権限が必要 |
| 重要度 | High | Medium |
| 修正状況 | 修正 PR は未マージ。修正版リリースは未確認 | 個別 Issue は未解決。修正版リリースは未確認 |
| 最初に確認すること | 外部公開範囲、`/api/proxy`、OpenAI API キーの利用履歴 | 保存済み JSON、共有 Volume、ホスト／コンテナの権限 |

対象バージョンを使っていなければ、今回の 2 件への直接対応は不要です。ただし、「キーが通る通信先」と「キーが残る保存先」を確認する考え方は、他の AI ツールにも応用できます。

## 重要インシデント

### 1. NextChat：細工された通信先へ OpenAI API キーが送られ得る（CVE-2026-82639）

- 重要度：High
- 証拠確度：Medium
- 状態：特定済み
- 期間：NVD 公表 2026 年 8 月 30 日 23:17（JST）。影響開始時刻は未公表
- 影響：NextChat 2.15.8～2.16.1。認証なしの攻撃者が細工した `x-base-url` を送ると、サーバーの `OPENAI_API_KEY` が攻撃者のホストへの Authorization ヘッダーに付与され得ます。
- 原因・対応：NextChat は通信先をホスト名の完全一致ではなく、`api.openai.com` という文字を含むかどうかで判定していました。ホスト名の検証とプライベート／メタデータ宛先の拒否を追加する修正 PR は公開されていますが、調査時点では未マージです。修正版リリースも確認できません。
- なぜ重要か：API キーが漏えいすると、第三者による API 利用や費用発生につながる可能性があります。実悪用、影響を受けた環境数、データアクセスの有無は未公表です。
- 一次情報：[NVD：CVE-2026-82639](https://nvd.nist.gov/vuln/detail/CVE-2026-82639)／[NextChat Issue #6814](https://github.com/ChatGPTNextWeb/NextChat/issues/6814)／[修正 PR #6884](https://github.com/ChatGPTNextWeb/NextChat/pull/6884)

この製品を使っている場合、「怪しい操作をした覚えがあるか」だけでは判断できません。外部から `/api/proxy` へ到達できる構成だったか、API キーの利用量や請求に心当たりのない変化がないかを、設定と記録から確認する必要があります。

### 2. browser-use web-ui：LLM API キーが平文ファイルとして残る（CVE-2026-82640）

- 重要度：Medium
- 証拠確度：Medium
- 状態：特定済み
- 期間：NVD 公表 2026 年 8 月 30 日 23:17（JST）。影響開始時刻は未公表
- 影響：browser-use web-ui 2.0.0～3.0.0。設定された LLM プロバイダーの API キーが、予測可能な名前の JSON ファイルへ平文保存され、一時設定ディレクトリを読める低権限の利用者に取得され得ます。
- 原因・対応：設定保存処理に暗号化や十分なアクセス制限がありません。プロジェクトの個別 Issue は調査時点で未解決で、修正版リリースは一次情報で確認できません。
- なぜ重要か：共有 Volume、複数利用者のホスト、他のコンテナから設定ディレクトリを読める構成では、プロバイダーの API キーが不正利用される可能性があります。ネットワーク経由だけで保存ファイルを取得できることは確認されていません。
- 一次情報：[NVD：CVE-2026-82640](https://nvd.nist.gov/vuln/detail/CVE-2026-82640)／[browser-use web-ui Issue #736](https://github.com/browser-use/web-ui/issues/736)

こちらは、インターネットへ公開しているだけで直ちにキーを取得される、という内容ではありません。確認すべきなのは保存先を誰が読めるかです。個人の端末だけで動かす場合と、チームで Volume を共有する場合では、同じバージョンでも実際のリスクが異なります。

## 実務への影響

すべてのキーを一律に交換する前に、次の順で確認すると、対応漏れや不要な作業を減らせます。

1. **製品とバージョンを確認する**
   NextChat 2.15.8～2.16.1、または browser-use web-ui 2.0.0～3.0.0 が稼働しているかを確認します。
2. **外部から届く範囲と、内部で読める範囲を分ける**
   NextChat は `/api/proxy` の外部公開範囲、browser-use web-ui は一時設定ディレクトリ、共有 Volume、ホスト／コンテナの読み取り権限を確認します。
3. **利用記録を確認する**
   OpenAI などの API 利用量、請求、キー利用ログに、心当たりのない変化がないかを確認します。
4. **露出が疑われる場合にキーをローテーションする**
   新しいキーへ切り替える場合は、非同期 Job や外部連携に古いキーが残っていないかも確認します。
5. **対応記録を残す**
   対象環境、確認結果、キー識別子、実施時刻を残しておくと、後から影響範囲を説明しやすくなります。

## 不明・要確認

- 2 件とも、実悪用、影響を受けた利用者数、実際の API キー漏えい、データへの不正アクセスは一次情報で確認できません。
- NextChat は修正 PR が未マージで、browser-use web-ui は個別 Issue が未解決です。開発元が確認した修正版、暫定的な回避策、公開環境への影響範囲は要確認です。
- browser-use web-ui は NVD 上の攻撃経路がローカルです。ネットワーク利用者が別のホスト／コンテナへの読み取り権限なしに保存ファイルを取得できるかは、一次情報で確認できません。
- Azure OpenAI Service は公開ページが地域別の稼働状況を示す一方、完全なインシデント履歴を提供しないため、対象期間の履歴網羅性は要確認です。

## おわりに

AI ツールを安全に使うために見るべきなのは、モデルの名前や性能だけではありません。API キーがどの通信を通り、どこへ保存され、誰が触れられるのか。今回の 2 件は、その確認を自分の環境へ引き寄せて考える材料になります。
